Coordinate cross-area changes with the relevant owners before merging.

## Changes

1. Create a focused branch for each feature or fix.
2. Keep changes inside the appropriate component folder where possible.
3. Update the relevant documentation and tests with behavior changes.
4. Do not commit credentials, local environment files, generated output, or
   private research data.
5. Use clear commit messages that explain the change.

As the individual components are implemented, add their exact install, run,
lint, and test commands to their local documentation.
